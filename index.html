One Question, End to End

What happens on the platform I built when someone asks a plain-English question. Simplified, but every step is real.

“Why did returns rise in the south last quarter?”

  1. 01 Ask
  2. 02 Route
  3. 03 Ground
  4. 04 Plan
  5. 05 Check access
  6. 06 Compute
  7. 07 Trace
  8. 08 Answer
  1. 01

    Ask

    The question arrives in chat. The answer streams back over SSE as it is built, so the person asking can steer the run or stop it midway.

  2. 02

    Route

    A router sorts the question as simple, moderate or complex, which sets its token budget and gives the agent only the tool groups it needs. The model is the one the user picked from 14 across Anthropic, OpenAI, xAI and Moonshot; prompt caching cuts the cost of repeat context, and the cost ledger reserves budget before the call goes out.

  3. 03

    Ground

    Ontology Studio resolves “returns” and “region” to published definitions of metrics and entities, so the answer is built on agreed meanings and cites them.

  4. 04

    Plan

    The agent chooses from 100 tools: SQL, charts, notebooks, ETL code. Anything risky, such as running a job or writing data, waits for a person to approve it.

  5. 05

    Check access

    Every statement is authorized for this user. Masking policies hide columns they may not see, and every query is written to the audit log.

  6. 06

    Compute

    The query runs on Spark 4 or DuckDB session pods over the Iceberg lakehouse, in under ten seconds on 100M+ rows, with results paged back as Arrow.

  7. 07

    Trace

    Column-level lineage shows which tables and columns fed the number, and flags drift when an upstream definition has changed.

  8. 08

    Answer

    A chart and a written answer come back with citations to the definitions used, and the ledger settles what the run actually cost.

gz — Data Platform CLI in Rust

One Rust binary, with a terminal UI, for a whole data platform: lakehouse SQL, files, ETL jobs, notebooks, models and agents, in 47 commands. Hard questions become one command, and gz jobs try runs a changed job on branches of the real tables before anything is published. 

# which commit broke this table?
$ gz bisect sales.orders --where "amount < 0"
# where does this number come from?
$ gz explain dataset revenue_by_region
# a job failed: hand it to the assistant
$ gz fix clean-orders

Proof: about 130k lines of Rust and 1,500+ tests; 200+ commits in seven weeks; released to v0.9.1 with checksum-verified installers and self-update on macOS, Linux and Windows.

headroom-scaler

A Kubernetes node autoscaler that adds nodes before pods exist. Usual autoscalers wait for pods to go Pending, so every burst waits minutes for a node. This one keeps bin-packed spare room per priority class, sized by usage and arrival rate, and provisions ahead of demand that workloads declare, such as "8 pods of 4 CPU from 02:00".

Proof: built at Groundzero. Pure first-fit-decreasing planner, lease-based leader election, AWS and KWOK providers, a Helm chart and 130+ tests. It never evicts or binds pods; it only resizes node groups and removes empty nodes.
